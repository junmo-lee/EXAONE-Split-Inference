# EXAONE 4.5 33B 임베딩 분할 성능 분석

CPU Transformer를 0개로 설정한 분할 경로는 4,096토큰 프롬프트에서
GPU-only 디코드 처리량의 **96.8%**를 유지했다. 첫 토큰은 **225 ms(10.8%)**
늦었으며 장치 VRAM 표본 최대치는 **1,373 MiB(6.4%)** 낮았다.

## 실험 설계

단일 RTX 4090에서 동일한 4,096토큰 합성 로그를 배치 1로 실행했다.
각 경로는 전체 길이 입력으로 워밍업한 뒤 3회씩 측정했다. CPU 스레드는
8개였으며 두 경로 모두 디코더 선형 계층을 NF4로 적재하고 greedy 토큰
선택을 사용했다. 여섯 실행 모두 같은 7개 토큰 ID(EOS 포함)를 생성했다.
이 일치는 해당 입력에 대한 검증이다.

공식 GPU-only 경로는 Transformers 멀티모달 래퍼를 GPU에 적재해 텍스트
입력을 실행한다. 분할에서는 CPU가 채팅 템플릿, 토큰화, BF16 임베딩,
최종 텍스트 디코딩을 맡는다. GPU 프로세스가 64개 Decoder 레이어, KV
캐시, 최종 RMSNorm·LM Head와 토큰 선택을 처리한다. TCP 요청에는 BF16
임베딩을 담고 응답에는 토큰 ID와 측정 메타데이터를 담는다. RTT 1 ms와
10 Gbps 직렬화 지연은 애플리케이션에서 가산했다.

| 지표 | 공식 GPU-only NF4 | CPU 임베딩 + GPU 64층 TCP |
|---|---:|---:|
| TTFT, 평균 ± 표본 표준편차 | 2.090 ± 0.001초 | 2.315 ± 0.007초 |
| 디코드, 평균 ± 표본 표준편차 | 12.50 ± 0.17토큰/s | 12.10 ± 0.31토큰/s |
| 장치 VRAM 표본 최대 | 21,614 MiB | 20,241 MiB |
| PyTorch CUDA 할당 피크 | 20.27 GiB | 18.18 GiB |

TTFT는 로딩, 채팅 템플릿·토큰화, TCP 연결·초기화를 제외한다. 디코드는
첫 토큰 이후부터 계산한다. 장치 VRAM은 nvidia-smi 표본 최대치이며
PyTorch 할당 피크와 집계 범위가 다르다.

## 시간 차이의 원인

| 토큰당 또는 프리필당 평균 | 프리필 1회 | 디코드 1토큰 |
|---|---:|---:|
| CPU 임베딩·클라이언트 토큰 처리 | 6.465 ms | 1.579 ms |
| GPU 계산 및 토큰 선택 | 2,087.951 ms | 79.086 ms |
| PCIe 복사 | 3.111 ms | 0.045 ms |
| 루프백 TCP·프레임 처리 잔여 시간 | 182.768 ms | 0.807 ms |
| 시뮬레이션으로 가산한 지연 | 34.653 ms | 1.078 ms |
| 전체 | 2,315.059 ms | 82.674 ms |

프리필 요청 페이로드는 4,096 × 5,120 × 2 B = 40 MiB이다. 프레임 헤더를
포함하면 41,943,120 B이고, 응답은 221~223 B였다. 요청과 응답의 직렬화
시간을 10 Gbps로 계산하면 약 33.56 ms이며 RTT 1 ms를 더한 값은 실측
가산 지연 34.65 ms와 부합한다. 루프백 잔여 시간과 가산 지연은 합계 약
217 ms로 공식 GPU-only와의 TTFT 차이 225 ms 중 대부분을 설명한다.
루프백 잔여 시간은 RPC에서 GPU·PCIe 시간을 뺀 값이라 직렬화, 소켓 I/O,
복사, 스케줄링을 개별적으로 구분할 수 없다. 세부 항목을 합산한 값과
전체의 작은 차이에는 계측 구간 밖의 준비 작업이 포함된다.

디코드 시에는 10,240 B의 임베딩 페이로드만 토큰마다 보내고 GPU 캐시에서
기존 문맥을 재사용한다. 평균 디코드 스텝은 GPU-only 80.00 ms, 분할
82.67 ms였다. 이미 작은 토큰 응답을 사용하기 때문에 프리필의 대형
요청과 같은 통신 비용이 매 스텝 반복되지 않는다.

## 메모리와 이전 4층 실험

분할 GPU 서버는 CPU가 보유한 임베딩과 텍스트 경로에서 쓰지 않는 비전
모듈을 적재하지 않는다. 공식 비교 경로는 멀티모달 래퍼 전체를 적재한다.
따라서 관측한 VRAM 차이는 두 적재 구성 전체의 차이다. 임베딩만 옮겼을
때 얼마나 절약되는지는 이 실험에서 따로 측정하지 않았다.

이전 4층 CPU 분할은 같은 4,096토큰 입력에서 TTFT 158.72초를 기록했고,
CPU 구간에 156.54초가 걸렸다. CPU 임베딩 전용 구성에서는 TTFT가
2.315초로 줄었다. 두 측정은 CPU 스레드 수(24개와 8개), 워밍업 및 GPU
디코더 적재 범위가 달라 엄격한 단일 변수 실험과는 구성이 다르다. 다만
각 실행의 시간 분해에서 4층 CPU 프리필 병목이 사라지고, 남은 TTFT
차이의 대부분이 프레임 처리와 가산 지연이라는 점을 확인했다.

## 해석 범위와 재현

측정은 루프백 TCP에서 실행했다. 실제 10 Gbps LAN의 처리량, 재전송,
혼잡, NIC 복사와 암호화 비용은 측정 범위 밖이다. 표본은 경로당 3회,
입력 1종, 생성 7토큰이므로 다른 문맥 길이와 장시간의 디코드 성능은
별도 검증이 필요하다.

```bash
OMP_NUM_THREADS=8 MKL_NUM_THREADS=8 python -m experiments.long_prompt \
  --dir /path/to/EXAONE-4.5-33B --split 0 \
  --output results/embedding-only-rerun.json
```
