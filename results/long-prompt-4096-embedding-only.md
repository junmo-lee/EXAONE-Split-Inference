# 4,096토큰 비교 · CPU Transformer 0개

CPU는 채팅 템플릿, 토큰화, BF16 임베딩 조회, 완성된 텍스트 디코딩을 맡는다.
GPU는 64개 Transformer 레이어를 NF4로 실행하고 KV 캐시, 최종 RMSNorm,
BF16 LM Head 및 greedy 토큰 선택을 담당한다. TCP 요청은 BF16 임베딩을
포함하며 응답은 토큰 ID와 측정 메타데이터를 담는다.

| 지표 | 공식 GPU-only NF4 | CPU 임베딩 / GPU 64층 TCP |
|---|---:|---:|
| TTFT | 2.090 ± 0.001초 | 2.315 ± 0.007초 |
| 디코드 | 12.50 ± 0.17토큰/s | 12.10 ± 0.31토큰/s |
| 장치 VRAM 표본 최대 | 21,614 MiB | 20,241 MiB |

동일한 RTX 4090, 채팅 템플릿 포함 4,096토큰짜리 합성 로그, 배치 1,
CPU 스레드 8개를 사용했다. 양쪽 모두 전체 길이로 워밍업한 뒤 3회씩 측정했다.
모든 실행에서 EOS 포함 7토큰의 ID가 일치했고, 출력은
`The access color is amber.`였다. TTFT는 모델 로딩, 채팅 템플릿 및 토큰화,
세션 연결과 초기화를 제외한다. 디코드는 첫 토큰 이후다. ±는 표본 표준편차다.

분할의 TTFT는 GPU-only보다 평균 225 ms(10.8%) 길었고, 디코드 속도는
96.8%였다. 프리필에서 CPU 단계는 6.5 ms, GPU 단계는 2.088초였다.
41,943,120 B를 송신했고 응답은 221~223 B였다. RPC에서 GPU 실행과 PCIe
복사를 뺀 루프백 TCP·프레임 잔여 시간은 평균 183 ms였다. 1 ms·10 Gbps
조건은 애플리케이션에서 평균 34.65 ms를 가산해 모사했다. 대역폭에 따라
실제 TCP 소켓의 송신율을 제어하는 방식은 실험 범위에서 제외했다.
장치 VRAM은 nvidia-smi 표본 최대치다. 분할 서버는 CPU에 있는 임베딩 및
텍스트 전용 실행에 사용하지 않는 비전 모듈을 적재하지 않는다.

이전 CPU 4층 실험의 TTFT는 158.72초였다. 새 분할의 2.315초는 관측값
기준 약 68.6배 짧다. 이전 TCP 실행은 CPU 스레드 24개와 짧은 워밍업을
사용했다. [이전 실험](long-prompt-4096.md)
